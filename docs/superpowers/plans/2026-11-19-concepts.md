# Concepts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Concepts section (`/concepts`, `/concepts/<uid>`) beside Case Studies, sharing the case study layouts, reached from a Portfolio dropdown in the main menu.

**Architecture:** A `collections` config describes each section (Prismic type, base path, intro singleton, labels, CTA). The existing `CaseStudies` and `PostCaseStudy` pages take a `collection` prop and are mounted twice in the router. The header attaches a two-item dropdown to the Portfolio nav item. Prismic link maps, the preview resolver and the pre-render config learn the `concept` and `concepts_page` types.

**Tech Stack:** React 19, React Router 6, Vite, Tailwind 4, @prismicio/client 7, Vitest + Testing Library (jsdom).

**Spec:** `docs/superpowers/specs/2026-11-19-concepts-design.md`

## Global Constraints

- `/case-studies` and `/case-studies/<uid>` look and behave exactly as today.
- Case studies and concepts never mix: each list and each single page only reads its own Prismic type.
- Prismic types: `concept` (repeatable, copy of `case_study` + `location` Key Text), `concepts_page` (single, copy of `portfolio_page`). Title With Description gets `note` (Key Text) in both repeatable types.
- Note style: DM Sans 14px (`text-sm font-dm`), black at 60% opacity, 32px below the description (inside the existing `md:gap-8` column; `gap-4` on mobile).
- Concept CTA secondary button: "See more concepts" → `/concepts`. Case study CTA unchanged ("See more work" → `/case-studies`).
- Portfolio in the menu is not a link; it opens Case Studies / Concepts.
- The site must work before the Prismic types exist (empty list, fallback intro).
- Commits have no Claude co-author line.

## Review Focus

1. **A concept UID typed under `/case-studies/` (or the reverse):** shows the "not found" state for that section. Test in Task 3.
2. **Moving between `/case-studies` and `/concepts` in the menu:** the list must refetch, never show the other section's items. Test in Task 2 (mounted with distinct `key`s; second render queries the new type).
3. **Prismic Navigation's Portfolio item doesn't resolve to exactly `/case-studies`** (e.g. a web link with trailing slash, or a renamed label): the dropdown must still attach, or Concepts becomes unreachable. Match on link `/case-studies` (trailing slash ignored) or label "Portfolio" (case-insensitive). Test in Task 5.
4. **Touch screens at desktop width (no hover):** the dropdown opens on tap and closes on outside tap, Escape, or navigation. Test in Task 5 (click, Escape).
5. **Mobile menu panel height:** two extra links must not be clipped by the panel's `max-h-[500px]`. Change it to `max-h-[85vh] overflow-y-auto`; check at 390×700 in the browser (Task 5).
